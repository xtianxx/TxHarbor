## 1. 方法（同负载同故障对照；adr.md §3）

**路径定义**

- **A（PG-only）**：PostgreSQL + Anvil；013 接线关闭（无 Redis/Kafka、无发布器/消费者、无缓存/限流/容量门禁）。生产者的 Append 集成无条件生效，因此事件在 outbox 累积但不投递（adr.md §3 路径 A 明确允许，仅用于对照实验）。
- **B（全栈）**：PostgreSQL + Anvil + Redis + Kafka；缓存、限流、容量门禁、发布器与消费者全开。

**受控变量**：同一主机；同一 PG 镜像/规格；同一 Anvil 镜像；同一数据集与初始状态（种子请求 + 授权池，两路径一致）；同一负载生成器（固定速率阶梯与突发，见下表）；同一故障注入时间线（两路径一致；路径 A 无 Redis/Kafka 依赖，故障态按时间线记录但无依赖可注入）。

**故障时间线（两路径一致）**

| # | 状态 | 注入 |
|---|---|---|
| 1 | normal | 无 |
| 2 | redis_down | 停止 Redis（Kafka 保持） |
| 3 | kafka_down | 挂起 Kafka 进程（SIGSTOP，保留日志与位点；Redis 恢复） |
| 4 | dual | Kafka 挂起 + Redis 停止（PG/链保持） |
| 5 | recovery | 恢复 Kafka（SIGCONT）+ 启动 Redis，测量排空与消费追赶 |

**测量口径**

- API 延迟/吞吐/错误率：负载生成器逐请求采样（原始样本存证），百分位为线性插值；吞吐 = 完成请求数/窗口（排除预热）；错误率分子 = 非 2xx/3xx 响应（含 PD-1 可重试拒绝）与传输错误。
- RPC：链侧存款操作（Anvil JSON-RPC：setCode/sendTransaction/receipt 轮询）的逐次耗时作为 RPC 路径的实测代理；按调用类的服务端 RPC 延迟直方图不在本 feature 的指标集内（标待测/待裁决，见 §9）。
- 服务端序列：/metrics 暴露导出（限流/缓存/容量/outbox gauge）；outbox 待发、最老等待、尝试总数、消费缺口（published-not-applied）、Kafka 高水位与消费组已提交位点直接读真实 PG/Kafka；发布失败/隔离以发布器与消费者的结构化记录计数（其命令无 metrics 端点）。
- 追赶时间：恢复时刻起（250ms 轮询）到消费缺口归零；排空时间：恢复时刻起到 outbox 待发与消费缺口同时归零（界内未达则标待测）。恢复时刻执行一次 drill-local 退避清零（`next_attempt_at=now()`，与 B9 一致），使追赶/排空反映发布与消费能力而非退避相位；不改事件内容、不删除/覆盖事件。
- 资源：进程级 CPU（/proc/self/stat，CLK_TCK=100 假设）、RSS、/proc/self/io、命名空间网络计数与 PG 连接池；负载生成器与服务同进程，故 CPU/IO 为上界（见置信限制）。

## 8. 结论与置信限制

**数据支持的结论（仅限本机本负载本窗口；不构成生产容量结论）**

- 正常态查询 p95：A=47.5 ms，B=72.7 ms（跨重复中位数；原始样本存证）。
- 仅 Redis 故障：新提款创建错误率 A=0.0，B=1.0（B 的拒绝为 PD-1 已裁决的可重试 503 行为；存量流程与链上处理不受影响）。
- 仅 Kafka 故障：窗口内 outbox 待发增量 A=48.0，B=44.5（A 的累积源于「013 接线关闭但 Append 无条件」的路径定义，不代表降级；B 的累积为投递暂停、恢复后由发布器排空）。
- 恢复追赶（B）：消费缺口归零=0.3 s，全链路排空=0.3 s（跨重复中位数；未达界标待测）。
- 资源（正常态进程级 CPU，跨重复中位数）：A=1.1 s，B=1.4 s；RSS A=75.2 MiB，B=63.2 MiB（同进程含负载生成器，见限制）。

**Kafka/Redis 价值结论（PD-3 边界）**

上述数值只支持本机本负载下的对照观察：它们**不预判也不取消**Kafka/Redis 的范围；若结果支持调整范围，MUST 另行提交具体变更供用户决定（PD-3），本报告不自动删减、不自动扩大。

**置信限制**

- 单主机、容器化、短窗口（每状态 12s）与固定合成负载；不是生产负载回放，无生产容量结论。
- 负载生成器与服务（serve/发布器/消费者）同进程运行：进程级 CPU/IO 为包含生成器的上界；两路径测量口径一致，差值仍可比，绝对值不可直接外推。
- 百分位为线性插值；延迟为客户端观测（含本机 HTTP/容器网络），与生产跨网络观测不可比。
- Kafka 故障用进程挂起（保留日志与位点）模拟不可用；Redis 故障用容器停止/重启（同固定地址）。故障注入方式与真实故障模式存在差异。
- 故障期数据受「故障注入时刻 + 500ms 稳定 + 12s 窗口」影响；不同窗口长度会得到不同追赶/积压数值。
